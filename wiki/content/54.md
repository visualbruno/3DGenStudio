# Timeline

The dock at the bottom of the VFX Editor. **One track per system**, and the transport controls for the whole effect.

## The transport

Play, pause, step and restart live in the timeline header, along with the timescale. There is deliberately no second set of controls in the preview — one playhead drives the preview, the ruler and the curve editors, so the effect reads as one object everywhere.

`Space` toggles play/pause. Inside the board, `Space`+drag still pans the view.

## Effect length

The number beside the transport is the effect's duration. Change it there.

Duration matters more than it looks:

- it is the window a **looping** effect repeats over;
- it is the range the [Sprite Sheet](/wiki/53) bake samples;
- and it is the axis a **rate curve** is drawn against when a system has several spawn windows.

## Tracks are systems

Each track is one system of the effect. The track list on the left is also where you manage them:

| Control | What it does |
|---|---|
| Name | Click to rename. Selecting a track shows that system on the board. |
| **Mute** | Silences this system in the preview. |
| **Solo** | Silences every *other* system. |
| **+ / duplicate / delete** | Add, copy or remove a system. |

Mute and solo are **preview state only** — they are not saved into the effect and not exported. Solo wins over mute: the reason to solo something is to look at it alone, and having to unmute everything else first would make the button useless.

Adding a system lays down a working five-block skeleton, so a new track emits immediately with no warnings.

## Clips

The bars on a track are **clips** — the windows during which that system is allowed to spawn.

| Clip | Meaning |
|---|---|
| **Zero length** | The window opens at that time and stays open. This is the default every system starts with, and it is what "just emit" means. |
| **With a duration** | The system spawns only inside that window. |
| **Looping** | The window repeats to the end of the effect. |

Drag a clip to move it, drag its edge to trim it, and put **several clips on one track** to make the same system fire more than once — a puff at 0.2s and again at 1.1s is two clips, not two systems.

A **Spawn Burst** block fires its whole count at the instant a window opens. A **Spawn Rate** block emits continuously for as long as a window is open. That is the whole relationship between clips and the [Spawn](/wiki/56) stage.

Clip times are snapped to whole simulation steps, so a clip at 0.02s fires on the same frame every replay and every scrub.

## Staging an explosion

This is what the timeline is for. A convincing explosion is not one cloud, it is several with different start times:

1. **Fireball** — one burst at 0s, dead by 0.5s.
2. **Debris** — one burst at 0s, but a two-second lifetime so it outlives the fire.
3. **Smoke** — a rate window from 0.1s to 1.3s, so it starts just after the flash and keeps producing.

Open the **Grenade** or **Muzzle Flash** preset to see exactly that.

## Scrubbing

A particle simulation cannot be run backwards — to reach a moment, it has to be replayed to it. Short effects are snapshotted as they play, so dragging the playhead is instant. Heavy ones fall back to re-simulating in chunks and show a progress chip while they do.

Scrubbing backwards lands on exactly the same frame as playing forwards to it. That is guaranteed, and tested.

## Export

One clip per track maps natively onto both engines. Several *burst* clips map natively too — they become several burst entries.

Several overlapping *rate* windows on one track is the case that cannot always round-trip, and when it cannot the track shows an amber badge and the diagnostics strip names it. You learn at author time rather than at import time.
