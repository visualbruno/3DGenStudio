# Initialize

Runs **once per particle, at birth**. It decides where a particle starts, how it moves off, how long it lives and what it looks like to begin with.

Almost every property here wants **random between two** rather than a fixed number. Variety at birth is what separates an effect from a pattern.

## Particle properties

| Block | Properties | Notes |
|---|---|---|
| **Set Lifetime** | `lifetime` (1.5) | How long the particle lives, in seconds. Drives every *over life* curve. |
| **Set Size** | `size` (0.25) | In metres. |
| **Set Colour** | `color` (white) | Values above 1 are allowed and are how a hot core blows out. |
| **Set Rotation** | `rotation` (0) | A random start rotation stops repeated sprites looking cloned. |
| **Set Sprite Frame** | `flipbookFrame` (0) | Which cell of a sprite sheet to start on. |

## Where particles are born

The emitter shape. **Turn on the Emitters checkbox in the toolbar** to see it drawn as a wireframe — it is the fastest way to understand an effect you did not write.

| Block | Properties | Shape |
|---|---|---|
| **Position: Point** | `offset`, `jitter` | One spot. `jitter` softens it into a small sphere. |
| **Position: Sphere** | `radius`, `offset`, `rotation` + fill mode | `volume` fills it, `surface` makes a hollow shell. |
| **Position in Box** | `size`, `offset`, `rotation` | A volume. Used for rain, snow, dust and anything ambient. |
| **Position in Circle** | `radius`, `thickness`, `offset`, `rotation` | A disc. `thickness` 1 fills it, 0 makes a ring. |
| **Position: Line** | `start`, `end`, `thickness`, `spacing` + placement mode | A segment. `even` spreads each spawn batch along all of it. |
| **Position: Curve** | a **Path** of 2–24 points, plus `thickness`, `spacing`, `tangentSpeed` + placement mode | A line that bends. The points are **on** the curve — placing them is bending a wire, not dragging Bezier handles. |
| **Position: Mesh** | `mesh`, `scale`, `normalSpeed`, `offset`, `rotation` + sampling mode | Emits from a model. `surface` spreads evenly over the triangles; `vertex` snaps to its corners. |
| **Cone Emitter** | `angle`, `radius`, `speed`, `offset`, `rotation` | A shape *and* a velocity in one — jets, muzzle flashes, sprays. |

Every shape has `offset` and `rotation`, so an emitter does not have to sit at the origin facing up.

### The Path

**Position: Curve** is the one emitter whose shape is a *list* rather than a
set of numbers, so it gets its own editor above the ordinary parameters
instead of a row per point. Add a point and it lands **halfway between its
neighbours**, so refining a curve never changes the curve; the arrows reorder,
and the cross removes. Two points is a straight line, three or more bend it,
and twenty-four is the ceiling — past that a point list has stopped being an
editor, and the shape you want is a mesh emitter.

Because the path is a list and not a property, it has **no modes**: no curve
over life, no random range, no operator wire. If you want the path itself to
move, animate the whole system rather than its points.

Set **Tangent speed** above zero and particles leave *along* the path, which is
what makes it read as flow rather than as a curved sprinkling. **Placement**
decides where along it they appear: `random` scatters, `even` spreads each
spawn batch across the whole path, and `spacing` walks along it at a fixed
distance in metres — the distance is measured along the curve, not across the
chord, so a bend does not bunch the particles up.

**Position: Curve** is for a path: a whip crack, a bolt arcing to a target, sparks running along a cable. Its `spacing` is measured **along the curve in metres**, so 0.25 is 0.25 m of arc wherever the curve bends — and `even` really is even, rather than bunching particles where the curve is tight.

Set **Tangent speed** above zero and particles leave *along* the path. Without it a curve emitter reads as a curved scattering rather than as something flowing.

**Position: Mesh** needs a mesh assigned in its property panel. Until one is, every particle spawns at the emitter's offset — visibly wrong rather than invisible, which is deliberate.

## How particles move off

| Block | Properties | Notes |
|---|---|---|
| **Velocity Outward** | `speed` | Away from the emitter's centre. Explosions, shockwaves, bursts. |
| **Velocity in Direction** | `direction`, `speed`, `spread` | A chosen direction, with `spread` in degrees of cone. Rain, jets, wind. |
| **Velocity: Random** | `min`, `max` | A random vector per axis. The most chaotic option. |
| **Inherit Velocity** | `scale` | Takes some of the parent's motion. For sub-emitters — sparks thrown from a moving rocket should keep going forwards. |

The **Cone Emitter** already includes a speed, so it usually needs no velocity block at all.

## Order matters

Blocks run top to bottom, so a later block overwrites an earlier one writing the same thing. Two shape blocks means the second wins.

That is occasionally useful — a Position in Circle followed by a Cone Emitter gives a ring-shaped jet — but if a shape appears to be ignored, this is why.

## In the engines

Every shape here has a native equivalent in Unity's particle system, and mode choices map across (`surface` becomes a shell, `thickness` becomes radius thickness).

Three carry a caveat under the Unity importer, and each is reported per import:

- **Velocity: Random** and **Velocity in Direction** become a velocity applied *over life* rather than drawn once at birth, so drag and gravity read slightly differently.
- **Position: Line** has no native equivalent and becomes a thin box along the segment.
- **Position: Curve** has none either — neither engine has a spline emitter a plugin can build unaided — so it becomes the straight chord between its end points and the bend is lost. If the shape of the path *is* the effect, bake it to a [Sprite Sheet](/wiki/53) instead.

**Velocity Outward** is exactly native — Unity emits along the shape's normal, which is the same thing.
