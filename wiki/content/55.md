# Nodes

The board shows how one system produces particles. It reads left to right:

```
Spawn  →  Initialize  →  Update  →  Output
```

| Stage | When it runs | Page |
|---|---|---|
| **Spawn** | Decides how many particles are born this frame | [Spawn](/wiki/56) |
| **Initialize** | Once per particle, at birth | [Initialize](/wiki/57) |
| **Update** | Every frame, for every living particle | [Update](/wiki/58) |
| **Output** | How the particles are drawn | [Output](/wiki/59) |

Each of those is a **node**, and each node holds a **stack of blocks** that run top to bottom.

## Blocks

A block is one instruction: *set the size*, *add gravity*, *collide with the floor*.

- **Add block** at the bottom of a node opens the palette, filtered to blocks that make sense in that stage.
- Rows are **collapsed by default** and show a summary of their value — "9.8 m/s² down" — so a five-block node reads as a list.
- Drag the handle to reorder. `Alt`+`↑`/`↓` does the same from the keyboard.
- A disabled block says the word **Off**.

**Order matters inside a node.** Blocks run top to bottom, so a Set Size below a Size Over Life will overwrite it. If something looks like it is being ignored, check whether a later block is writing the same thing.

Two things are *not* blocks and cannot be reordered: ageing (and killing) runs before your Update blocks, and the integrator that turns velocity into movement runs after them. Neither Unity nor Unreal exposes those either.

## Property modes

Every property can be more than a fixed number. Click the mode switch on a property row:

| Mode | Use it for |
|---|---|
| **Constant** | One value. |
| **Random between two** | Variety per particle — the single most useful mode. A burst where every particle has the same lifetime reads as a machine. |
| **Curve over life** | A value that changes as the particle ages. |
| **Gradient over life** | The same, for colour. |
| **Wired** | Driven by an operator node. |

Switching modes is **non-destructive**: switch a curve back to a constant and the curve is kept, so switching back restores it.

Curves and gradients are property *modes*, not nodes — so the common case needs no wiring at all.

## The curve editor

Opens from a property in the Parameters panel.

- Click empty space to add a key, drag to move it.
- Double-click a key to cycle smooth → linear → stepped.
- `Shift` locks to one axis, `Ctrl` snaps.
- **Edit as numbers** is a real table if you want exact values.

The **playhead** is the useful part: it draws a tick for every living particle at its own point on the curve. Watching the population sweep across is what makes the curve and the effect visibly the same thing.

## The gradient editor

Alpha rail on top, colour rail below, with the composited result between them.

Clicking an empty rail adds a stop **sampled from the gradient at that point**, so adding a stop never changes the look. Each colour stop has a **brightness** field above 1 for HDR — that is how a bright core blows out through the tonemapper, and it exports to both engines.

## Operators

Small nodes that compute a value and feed it into a block property: `Value`, `Add`, `Subtract`, `Multiply`, `Divide`, `Blend`, `Clamp`, `Remap`, `Oscillate`, `Random Per Frame`, `Effect Time` and `Particle Attribute`.

Drag from an operator's output onto a block row and pick which property to drive. A second wire into the same property replaces the first.

Reach for these when a value has to depend on something else — the effect's own time, a particle's speed, a shared number used in three places. For anything simpler, a curve on the property is less work and exports more cleanly.

## Notes and tidying

Right-click the board for a note. **Tidy** lays the nodes out again. Node positions are never read by the compiler, so moving a node never restarts the effect.
