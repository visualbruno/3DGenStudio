# Spawn

How many particles are born, and when. Two blocks.

| Block | Property | Default |
|---|---|---|
| **Spawn Rate** | `rate` — particles per second | 50 |
| **Spawn Burst** | `count` — particles at once | 20 |

A system can have both: a burst at the start and a rate afterwards is how a jet that begins with a puff is built.

## Rate or burst?

**Spawn Rate** produces a continuous stream for as long as a spawn window is open. Fire, smoke, rain, a torch, a magic aura — anything that is *ongoing*.

**Spawn Burst** produces its whole count in a single frame, at the instant a window opens. Sparks, an explosion, a hit, a pickup twinkle — anything that *happens*.

## Spawn works with the Timeline

The Spawn stage says *how many*. The [Timeline](/wiki/54) says *when*. A clip is a window during which this system is allowed to spawn:

- a **burst** fires each time a window opens — so three clips on the track means three bursts;
- a **rate** emits for as long as a window is open.

The default clip every system gets is open-ended, which is why a new system with a Spawn Rate block just emits.

## Capacity, and dropped particles

Each system has a **capacity** — the maximum number of particles alive at once. It is fixed when the effect compiles and never grows while it runs.

Roughly: `rate × lifetime` is how many particles a rate system will have alive. 200/s with a 3-second lifetime needs 600.

When a system is full, new spawns are **dropped and counted**. The stats window shows `dropped`, in red when it is not zero. Dropping visibly beats hitching invisibly, but it does mean an effect quietly emitting less than you asked for — so if a stream looks thinner than it should, check that number first.

The diagnostics strip warns before it happens, with the arithmetic spelled out, and offers to raise the capacity.

## Getting a burst to look natural

A burst is instantaneous, so every particle is born on the same frame. If they also share a lifetime they will all die on the same frame, which reads as a machine rather than an event.

Set **Set Lifetime** to *random between two* — say 0.3 to 0.85 — and the burst decays instead of switching off. The same trick applies to size and speed. This is the single most common fix for an effect that looks synthetic.

## Cost

Spawn rate is the number that decides what an effect costs. Before raising it, check the stats window: `alive`, `sim ms` and `draws`.

The usual reason an effect is slow is not the particle count but **overdraw** — hundreds of large transparent quads stacked on the same pixels. Fewer, smaller particles almost always looks better and costs less than more, larger ones.

## In the engines

Both Unity and Unreal take rate and burst natively.

Under the Unity importer, spawn windows become a rate **curve over the effect duration** with stepped keys, so several windows survive exactly. Bursts become native burst entries, with looping clips becoming a repeating burst.
