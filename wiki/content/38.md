# Mesh

Export a single mesh to a standard 3D file format, with engine-ready presets for Blender, Unity and Unreal. This is how you take a finished asset out of 3DGenStudio and into a game engine or another DCC tool.

## Where to export from

- **Mesh preview** — open a mesh asset's preview, then click **Export**. This path can carry the asset's **rig and animation clips**, so it offers the full set of engine presets.
- **Mesh Editor** — the editor can also export the mesh you're working on. Because the editor hands over rig-free geometry, only the plain geometry formats (GLB, OBJ, PLY, STL) are offered there.

## Exporting

1. Click **Export** to open the export dialog.
2. Choose a **format** (see below).
3. Set the **file name** — the extension is filled in automatically for the chosen format.
4. Choose an **output folder** — type the path or click **Browse**.
5. Click **Export**. A progress bar is shown for formats that need conversion, and a success message lists the files that were written.

## Formats

| Format | File | Notes |
| --- | --- | --- |
| **GLB** | `.glb` | Single file with textures embedded. The default. |
| **Blender — GLB (rig + animations)** | `.glb` | Blender imports GLB natively (*File → Import → glTF 2.0*) with the skeleton and every animation clip. GLB source assets are copied byte-for-byte for perfect fidelity. |
| **Unity — FBX (rig + takes)** | `.fbx` | Drop the `.fbx` into *Assets*. Textures are embedded — use *Materials → Extract Textures*. Pick the rig type under *Rig* (Humanoid may need *Enforce T-Pose*); each clip appears as a separate take. |
| **Unreal Engine — FBX (cm, rig + takes)** | `.fbx` | Import as a *Skeletal Mesh* with *Import Animations* enabled. Exported in centimeters at scale 1 — no unit conversion needed. |
| **FBX — generic (rig + takes)** | `.fbx` | Neutral FBX (meters, Y-up) with the skeleton and one take per clip. Suitable for Godot, Maya, 3ds Max and other DCC tools. |
| **OBJ — geometry + .mtl + textures** | `.obj` | Saves geometry, materials and textures as separate files named after the mesh (e.g. `mesh.obj`, `mesh.mtl`, `mesh_albedo.png`). |
| **PLY** | `.ply` | Geometry only. |
| **STL** | `.stl` | Geometry only. |

> The **FBX presets** (Unity, Unreal, generic) convert through the **Mesh Tools service**, which the app starts automatically when you export. GLB and the geometry-only formats (GLB, OBJ, PLY, STL) export directly and need no service.

## Rig and animations

The FBX and Blender presets exist specifically to carry a mesh's **skeleton and animation clips** into an engine. When the source asset is already a `.glb`, its original bytes are used so skin weights, clips and textures are preserved exactly. Otherwise the mesh is serialized through three.js, which still carries the loaded animations onto the export. After an FBX conversion the success message reports the bone and clip counts that were written.

## Flatten to one lit albedo (mobile)

A PBR material is several textures and a shader that combines them per pixel, which is exactly what a mobile game often cannot afford. Keeping only the original base colour is cheap but loses most of the look: the normal-map detail, the contact shadows, the difference between metal and paint. **Flatten to one lit albedo** keeps that look by baking it into a single colour texture, lit by a neutral studio, and gives every mesh a material that uses it. Parts that render differently in the source — double-sided, cut-out or blended — keep that behaviour on their own copy of the material, so an asset ends up with one material in most cases and a handful at most, all sharing the one texture.

What is deliberately **not** baked in is anything that belongs to one viewpoint or one light: specular highlights, reflections of nearby parts, and cast shadows. Contact darkening (in creases, under overhangs) is kept, because it comes from the soft dome rather than from the key light. Baked into a texture they would stay stuck on the surface from every angle. Metals keep their own colour (under the studio dome they reflect a soft neutral grey, not black).

Pick the **target shader** your game will draw the mesh with:

| Target shader | What is baked | Exported material |
| --- | --- | --- |
| **Unlit** | A soft dome brighter overhead than underfoot, plus a gentle, shadowless key light from the upper front-left. The texture is the only light the mesh will get, so it carries the shape. | GLB: `KHR_materials_unlit` (Unity's glTFast and UnityGLTF import it as an unlit shader). FBX/OBJ: a plain textured material — assign an unlit shader in the engine. |
| **Simple lit** | Contact shadows and a mild top-down fill only, no key light — the game's own light supplies the direction, and a baked one would double it. | A rough, non-metal material with the albedo — ready for a Lambert / simple-lit shader. |

The other settings:

- **Resolution** — the one texture now holds every material, so it usually needs more pixels than any single source texture had (2048 is a good start for a character).
- **Samples** — how many light paths Cycles traces per texel. 64 is clean on open surfaces; raise it to 128+ if cavities look grainy. 16 is a quick preview.
- **Exposure** — brightens or darkens the bake, in stops. The success message warns when a lot of the texture reached the highlight roll-off.

How it works: the mesh's existing UV islands are **repacked** into one shared atlas (a layout that is already a clean single atlas is kept as-is), so the geometry, the **rig, skin weights, morphs and animation clips come through unchanged**. Parts with no usable UVs get a small island per triangle; if there are too many of those, run **Auto UV** in the Mesh Editor first. Cut-out and transparent parts (leaves, lace, glass) keep their alpha, and only those parts.

The flatten runs first, so everything after it works from the flattened mesh: a **LOD chain** simplifies it, and *Bake textures from the original* re-bakes just the flattened albedo onto each level. It needs the **Mesh Tools service** (a lit Cycles bake in headless Blender): seconds for a simple prop, a few minutes for a dense character at 4096px.
